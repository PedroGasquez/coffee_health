Bibliotecas e configuração

O que o código faz

  1. RAIZ encontra a pasta do repositório, seja o notebook aberto em notebooks/ ou na raiz.
  2. load_dotenv lê o arquivo .env, onde ficam os valores fixos do projeto (regra do CLAUDE.md: nada de números mágicos no código).
  3. os.getenv(nome, padrão) busca cada valor; o segundo argumento só é usado se o .env não existir.
  4. int() e float() convertem o texto lido para número.
18valores configuráveis no .env, de semente aleatória a faixas etárias

Q1 · Carga e conhecimento do dataset

O que o código faz

  1. Antes de ler, o código confere se o CSV existe e explica como corrigir o caminho se não existir.
  2. df_original guarda os dados como vieram; df é a cópia que recebe as transformações. O CSV nunca é regravado.
  3. df.shape devolve a tupla (linhas, colunas).
  4. dtypes mostra o tipo de cada coluna, e describe() resume as numéricas (média, desvio, quartis).

Q2 · Valores ausentes e duplicados

O que o código faz

  1. isnull() marca True onde falta valor; .sum() conta por coluna e .mean() dá a proporção.
  2. No CSV, os ausentes de Health_Issues estão escritos como None, e o read_csv os converte em NaN.
  3. São três testes de duplicidade: linha inteira repetida, linha repetida ignorando o ID e ID repetido.
59,41%de Health_Issues ausente (5.941 registros) e nenhum duplicado

ETL · Transformação dos dados

O que o código faz

  1. Extração: parte sempre de uma cópia de df_original.
  2. Duplicados: drop_duplicates() remove linhas repetidas, se houver.
  3. Ausentes: fillna troca o vazio por "Não informado", porque ausência não significa "sem problema de saúde".
  4. Ordinais: pd.Categorical(..., ordered=True) faz o pandas entender que Poor < Fair < Good < Excellent.
  5. Anonimização: o ID sai, porque identifica o registro e não entra nas análises.
10.000 × 15DataFrame limpo, sem ausentes e sem o ID

Q8 · Árvore de decisão

O que o código faz

  1. X são os seis atributos pedidos (sem o ID) e y é a classe que o modelo deve prever.
  2. train_test_split separa 80% para treino e 20% para teste; stratify=y mantém a proporção das classes nos dois.
  3. max_depth limita a profundidade da árvore para evitar overfitting (sem limite: 100% no treino e 38,9% no teste).
  4. A acurácia é comparada com a baseline de prever sempre a classe mais comum.

LGPD e ética

LGPD · Medindo o risco de reidentificação

O que o código faz

  1. Quase-identificadores não identificam ninguém sozinhos, mas combinados podem identificar.
  2. groupby(...).size() conta quantas pessoas têm cada combinação.
  3. k-anonimato: todo grupo precisa ter pelo menos K_ANONIMATO pessoas; um grupo de 1 aponta direto para alguém.
  4. A função é reutilizada para comparar o antes e o depois da anonimização.
89,1%dos registros em grupos com menos de 5 pessoas, usando a idade exata

LGPD e ética

LGPD · Generalização e supressão

O que o código faz

  1. Generalização: pd.cut troca a idade exata por faixas (18–29, 30–44 e 45–80), definidas no .env.
  2. transform("size") escreve em cada linha o tamanho do grupo a que ela pertence.
  3. Supressão: o filtro descarta quem continua em grupo menor que k.
  4. O df original segue intacto para as análises; só df_compartilhavel sairia do ambiente.
0%em risco depois da proteção, mantendo 97,6% dos registros

Conclusões

  • Mais café aparece junto de pior sono e mais estresse, sem relação de causa e efeito.
  • Várias colunas sintéticas repetem a mesma informação: cafeína acompanha o café, e estresse e qualidade do sono seguem as faixas de horas de sono.
  • Os seis preditores da Q8 não separam a qualidade do sono melhor que a baseline.
  • Generalização e supressão protegem os titulares e preservam 97,6% dos dados.
